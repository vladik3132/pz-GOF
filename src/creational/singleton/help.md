Сінглтон — це "один об'єкт на всіх

1. Файл Settings.ts (Серце патерна)
Це "сейф", де лежать наші дані.

private static instance: Settings;

Це статична змінна, яка зберігає єдиний екземпляр класу. Вона static, тому належить самому класу, а не конкретному об'єкту.

private constructor()

Найважливіша частина! Модифікатор private забороняє використовувати new Settings() в інших файлах. Якщо ти спробуєш це зробити, TypeScript видасть помилку. Тільки сам клас може створити себе.

public static getInstance(): Settings

Це "єдине вікно" видачі об'єкта.

Логіка: Якщо instance ще порожній (перший виклик) — створюємо об'єкт. Якщо вже є — просто повертаємо той, що лежить у пам'яті.

public language: string

Це наші дані. Оскільки об'єкт один, то зміна цієї змінної відобразиться всюди.

2. Файл Logger.ts (Клієнт-спостерігач)
Цей файл імітує ситуацію, коли нам потрібні налаштування в іншому модулі.

const settings = Settings.getInstance();

Тут ми не створюємо нові налаштування. Ми кажемо: "Гей, Клас Settings, дай мені той єдиний екземпляр, який у тебе є".

console.log(...)

Він просто читає значення language. Оскільки об'єкт спільний, Logger завжди бачить найактуальнішу мову.

3. Файл index.ts (Директор/Запуск)
Тут ми перевіряємо, чи працює наша "магія".

const mySettings = Settings.getInstance();

Отримуємо доступ до налаштувань у головному файлі.

mySettings.language = "English";

Ми змінюємо мову. Оскільки mySettings посилається на той самий об'єкт, що і settings всередині Logger.ts, зміни відбуваються миттєво для всієї програми.
